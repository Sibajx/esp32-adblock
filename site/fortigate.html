SiBlock detrás de un FortiGate

Para quien administra un FortiGate (FortiOS 7.x).

No hace falta saltarse el FortiGate. Se configura para que reparta SiBlock como el DNS de la red. Antes de empezar, guarda una copia de la configuración.

Pasos

  1. Reserva la dirección de SiBlock

    Dashboard → Network → DHCP → clic derecho sobre SiBlock → Create reservation.

  2. Reparte SiBlock como único DNS

    En la interfaz interna: DHCP Server → DNS server Specify → la dirección de SiBlock, sin segundo DNS. Si hay otro, los aparatos lo usan a ratos y se saltan el bloqueo. 

    config system dhcp server
    edit <id>
        set dns-service specify
        set dns-server1 <IP-del-ESP32>
        unset dns-server2
    next
end

    <IP-del-ESP32> es la dirección de tu SiBlock; <id> es el número del servidor DHCP de esa interfaz.

  3. No toques el DNS propio del FortiGate

    Network → DNS sigue con FortiGuard o un DNS público. Si lo apuntas a SiBlock y la placa se apaga, el FortiGate pierde sus servicios.

  4. Que nada intercepte el puerto 53

    Sin VIP ni DNAT al puerto 53 y sin DNS Service en la interfaz interna. El perfil DNS Filter de la política puede quedarse.

  5. Deja salir a SiBlock

    Si tus políticas son estrictas, permite desde SiBlock: DNS (UDP y TCP 53) a 1.1.1.1 y 9.9.9.9, HTTPS a GitHub (para bajar las listas) y la hora (NTP, UDP 123).

  6. Opcional: que nadie se salte SiBlock

    Permite DNS (puertos 53 y 853) hacia internet solo desde SiBlock y niégalo al resto de la red. Ojo: puede afectar computadoras del trabajo o con VPN.

  7. IPv6

    Apaga el DNS que anuncia la interfaz (RDNSS / DHCPv6).

  8. Prueba

    Renueva el DHCP de un aparato y revisa que su DNS sea SiBlock. Luego nslookup doubleclick.net debe contestar 0.0.0.0, y el aparato debe salir en tu panel.

  9. Deshacer

    En el mismo servidor DHCP, regresa el DNS al de siempre:

    config system dhcp server
    edit <id>
        set dns-service default
    next
end

¿Otro firewall?

Sophos, SonicWall, WatchGuard, pfSense y otros tienen el mismo problema: contestan o desvían las consultas de DNS. La idea es la misma, pero todavía no hay guía para cada uno. Mira los problemas comunes en la red.
